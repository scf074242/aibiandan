## 阶段三：回退与修补机制（第5-6天）

### Day 5：三级回退机制

**目标**：实现健壮的错误恢复

**任务清单**：

1. **创建回退管理器** `src/services/fallbackManager.ts`
   - **条目级回退**：换候选重新写入
     - 记录条目快照
     - 回退到上一状态
     - 尝试新候选
   - **空窗级回退**：回退空窗内最近若干条
     - 记录空窗处理历史
     - 批量回退条目
     - 重新计算空窗
   - **会话级回退**：暂停自动编排，转人工
     - 保存当前会话状态
     - 生成问题报告
     - 转人工处理接口

2. **快照管理**
   - 写入前自动创建快照
   - 快照存储和检索
   - 快照清理策略

3. **回退策略配置**
   - 最大重试次数配置
   - 自动/手动回退开关
   - 回退阈值设置

**验收标准**：
- [ ] 三级回退机制实现
- [ ] 回退后状态正确恢复
- [ ] 空窗列表正确重算

## 关键依赖关系

```
回退管理器 ──> 原子能力服务（快照）
    │
    └──> 空窗管理器

修补管理器 ──> 校验引擎
    │
    └──> 命令执行器
    │
    └──> LLM 客户端

数据服务 ──> 各类接口层
    │
    └──> 编排调度器

UI 组件 ──> 组合式函数 ──> 编排调度器
```

## 风险点

| 风险 | 应对措施 |
|------|----------|
| 回退机制状态管理复杂 | 完善的快照和恢复机制 |
| 修补循环无法收敛 | 有限轮次 + 收敛性检测 |
| UI 组件与旧版本兼容 | 渐进式替换，保留旧组件 |
| 集成测试覆盖不足 | 编写单元测试 + 端到端测试 |
