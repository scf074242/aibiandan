# 修复 create.vue 页面计划 v2

## 问题诊断

1. **路由错误**: router/index.ts 引用了 `../views/demo/OrchestrationDemo.vue`，但 demo 目录可能不存在或文件不完整
2. **create.vue 需要更新**: 需要将新开发的编排功能正确集成到 create.vue 页面

## 正确的交互流程

根据技术方案，正确的流程应该是：

```
用户输入自然语言需求
    ↓
LLM 任务判别器分析 → 自动得出任务模式
    ↓
根据任务模式执行相应编排逻辑
    ↓
展示编排进度和结果
```

**不是**: 让用户手动选择6种任务模式
**而是**: 用户在对话框输入需求，系统自动分析并执行

## 修复步骤

### 步骤 1: 修复路由配置
**文件**: `src/router/index.ts`
- 移除对 demo/OrchestrationDemo.vue 的引用
- 保持首页指向 create.vue

### 步骤 2: 重新设计 create.vue 的编排抽屉
**文件**: `src/views/broadcast-plan/create.vue`

**简化编排抽屉为3个标签页**:
1. **AI 助手** - 对话面板（主要入口）
   - 用户输入自然语言需求
   - LLM 自动分析任务模式
   - 显示命令预览和解释

2. **编排进度** - 显示执行状态
   - 空窗处理进度
   - 回退状态
   - 修补轮次
   - 执行日志

3. **AI 配置** - LLM 参数设置

**移除**: 任务模式选择器（不需要用户手动选择）
**移除**: 空窗可视化（可以集成到编排进度中或作为独立功能）

### 步骤 3: 更新对话面板集成
- 对话面板作为主要交互入口
- 用户输入需求后，调用 taskClassifier 进行任务判别

### 步骤 4: 验证类型导入和组件引用

### 步骤 5: 运行测试
- 运行 TypeScript 类型检查
