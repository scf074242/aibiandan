|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 架构变更 | 为 LLM interpretation 失败建立结构化可恢复状态 | 自由体验/定向检查 | 当前 `schedulingAgentRuntime` 在 interpretation 为空时直接返回 failed，既没有 capability 兜底，也没有可恢复的业务 evidence | LLM 偶发失败或输出格式异常时，系统仍应保护主流程可解释、可重试、可审计 | 新增 `recoverable_interpretation_failure` envelope，包含 recognizedSlots、rawUserInput、safeActions、retryOptions、noMutation guarantee | 改 runtime contract、server response、ChatPanel renderer 和测试 | 所有 Agent Core 自然语言入口 | P0 | L | 需避免把本地分类器扩成主理解层 | 解释失败不再只有固定文案；前台能展示可恢复动作；审计里记录 noMutation | 先写 contract 文档，再改最小纵切 |
| 架构变更 | 统一多层 timeout/deadline 策略 | 自由体验/定向检查 | 代码中存在 6s、15s、30s、60s 多种 timeout；前台观测到 30s 失败和更长等待不确定，用户无法理解系统状态 | 真实素材库、LLM 和服务端任务都可能慢，需要一致的 SLA 和取消模型 | 引入 request-level deadline：前台显示、server submit、LLM call、planner/retry 都继承同一个 deadline 和 abort signal | 跨模块改造，建议先从 `/api/agent/submit` 纵切 | 所有自然语言请求、ReAct、候选检索 | P0 | L | 依赖事件流和任务停止兼容 | 日志和 UI 使用同一个 request id/deadline；超时文案一致；取消能中止下游 | 先实现 submit request id + deadline trace |
| 架构变更 | 将 preview_only/noMutation 作为跨模块硬约束 | 自由体验 | 用户说“别直接写正式播单”只存在于自然语言里，没有体现为跨 runtime、pending、write adapter 的强约束 | 编排员常要求“先看方案”，这是安全边界，不是普通文案 | 在 intent result、planner action、pending command、write adapter 中传递 `mutationPolicy: preview_only | confirm_required | allow_write` | 需要状态模型和写入 adapter 一致处理 | 草案更新、正式写入、候选推荐、原子命令 | P0 | L | 影响现有快捷动作和测试 | preview_only 下任何 write adapter 调用都会被拒绝并审计；UI 显示只读预览 | 与候选/原子预览模式一起落地 |
